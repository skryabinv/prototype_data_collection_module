# Протокол обмена данными STM32H743 ↔ Jetson Orin Nano: Архитектура, датчики и интеграция с ROS2

**Проект:** Цепкий Глаз Техпром  
**Дата публикации:** 17 сентября 2026 г.

В современных робототехнических и дроновых системах критически важна надежная и быстрая связь между микроконтроллером (MCU), отвечающим за сбор телеметрии, и одноплатным компьютером (SBC), выполняющим тяжелые вычисления. В данной статье мы подробно разберем протокол обмена данными между модулем сбора данных на базе **STM32H743** и вычислительным модулем **Jetson Orin Nano**.

Протокол разработан для передачи данных с барометра BMP390 и магнитометра MMC5983MA, а также для их динамического конфигурирования.

---

## 1. Архитектура и физический уровень

*   **Физическая среда:** UART
*   **Архитектура:** ARM Cortex-M7 (STM32) ↔ ARM Cortex-A (Jetson)
*   **Порядок байт:** Little-Endian (на обеих сторонах)
*   **Языки реализации:** C++ (STM32, Jetson), Python (опционально для ROS2)

### Метод фреймирования
Протокол использует комбинацию **магического слова (Magic Word)** и **префикса длины (Length-Prefixed)**. 
*   **Сигнатура начала:** `0xAA 0x55`
*   **Обоснование:** Такой подход обеспечивает простую реализацию парсера, легкую отладку через HEX-терминал, низкую вероятность ложного срабатывания на мусорных данных и полную совместимость с ROS2 serial-пакетами.

### Структура пакета
Каждый кадр имеет следующий формат:

| Смещение | Размер | Название | Описание |
| :--- | :--- | :--- | :--- |
| 0 | 1 байт | `SYNC_1` | Сигнатура начала пакета: `0xAA` |
| 1 | 1 байт | `SYNC_2` | Сигнатура начала пакета: `0x55` |
| 2 | 1 байт | `MSG_ID` | Идентификатор сообщения |
| 3 | 1 байт | `LENGTH` | Длина полезной нагрузки (0-255 байт) |
| 4..N | N байт | `PAYLOAD` | Полезные данные (зависят от `MSG_ID`) |
| N+1 | 1 байт | `CRC` | Контрольная сумма (CRC-8) от байт `[2..N]` |

> **Важно:** CRC-8 (полином `0x8C`, алгоритм MAXIM) рассчитывается от `MSG_ID`, `LENGTH` и `PAYLOAD`. Сигнатуры `0xAA 0x55` в расчет **не включаются**.

## 2. Идентификаторы сообщений (MSG_ID)

Данные с датчиков разделены на независимые пакеты. Это позволяет BMP390 и MMC5983MA работать на разных частотах (ODR), публиковать данные в ROS2 асинхронно и снижает нагрузку на парсер.

| MSG_ID | Название | Направление | Описание |
| :--- | :--- | :--- | :--- |
| `0x01` | `SENSOR_DATA_BMP390` | STM32 → Jetson | Данные с барометра |
| `0x02` | `SENSOR_DATA_MMC5983MA` | STM32 → Jetson | Данные с магнитометра |
| `0x03` | `CONFIG_CMD` | Jetson → STM32 | Команда конфигурирования датчиков |
| `0x04` | `ACK` | STM32 → Jetson | Подтверждение выполнения команды |
| `0x05` | `ERROR` | STM32 → Jetson | Сообщение об ошибке |

## 3. Форматы полезных нагрузок

### 3.1. Пакет данных с BMP390 (`MSG_ID = 0x01`)
Размер payload: 13 байт. Общий размер кадра: 18 байт.

```cpp
#pragma pack(push, 1)
struct Bmp390DataPayload {
    uint32_t timestamp_us; // Время измерения (мкс от старта MCU)
    float pressure_pa;     // Давление в Паскалях
    float temp_c;          // Температура в °C
    uint8_t status_flags;  // Флаги состояния
};
#pragma pack(pop)
```
*Флаги состояния:* Бит 0 (`BMP_OK`) — датчик работает; Бит 1 (`DATA_READY`) — данные актуальны.

### 3.2. Пакет данных с MMC5983MA (`MSG_ID = 0x02`)
Размер payload: 21 байт. Общий размер кадра: 26 байт.

```cpp
#pragma pack(push, 1)
struct Mmc5983maDataPayload {
    uint32_t timestamp_us; // Время измерения (мкс от старта MCU)
    float mag_x_gauss;     // Магнитное поле X (в Гауссах)
    float mag_y_gauss;     // Магнитное поле Y
    float mag_z_gauss;     // Магнитное поле Z
    float temp_c;          // Температура в °C
    uint8_t status_flags;  // Флаги состояния
};
#pragma pack(pop)
```

### 3.3. Команды конфигурации (`MSG_ID = 0x03`) и Подтверждения (`MSG_ID = 0x04`)
Пакет конфигурации позволяет менять настройки "на лету". Команда содержит `target_sensor` (0x00 - все, 0x01 - BMP390, 0x02 - MMC5983MA), `command_id` (например, `0x10` - SET_ODR, `0x70` - TRIGGER_SET_RESET) и `param_value`. 
В ответ STM32 отправляет `AckPayload` (3 байта), содержащий статус выполнения (от `0x00` - Успешно, до `0x04` - Команда не поддерживается).

## 4. Специфика работы с датчиками

### 4.1. Барометр BMP390
BMP390 требует **программной компенсации** сырых данных ADC. 
**Важно:** STM32H743 должен выполнять компенсацию по алгоритму из даташита и передавать на Jetson уже готовые физические значения (Па, °C).
*Рекомендуемые настройки для динамичной среды (дрон/робот):* Normal mode, Oversampling: Pressure x8 / Temp x1, IIR Filter: 2, ODR: 50 Hz.

### 4.2. Магнитометр MMC5983MA и процедура SET/RESET
MMC5983MA требует периодического выполнения процедуры SET/RESET для устранения температурного дрейфа и эффекта насыщения. 

**Алгоритм измерения:**
```cpp
// 1. Выполнить SET
write_register(0x09, 0x08); delay_ms(1);
// 2. Запустить измерение и прочитать Output1
write_register(0x09, 0x01); wait_for_measurement_done();
read_xyz_data(&out1_x, &out1_y, &out1_z);

// 3. Выполнить RESET
write_register(0x09, 0x10); delay_ms(1);
// 4. Запустить измерение и прочитать Output2
write_register(0x09, 0x01); wait_for_measurement_done();
read_xyz_data(&out2_x, &out2_y, &out2_z);

// 5. Вычислить реальное поле и перевести в Гауссы (18-bit режим)
mag_x = (out1_x - out2_x) / 2.0f;
mag_x_gauss = (mag_x - 131072.0f) / 16384.0f;
// Аналогично для Y и Z
```
*Частота SET/RESET:* Рекомендуется каждые 100-500 измерений, либо при изменении температуры на >5°C, либо включение автоматического режима (`Auto_SR_en = 1`).

## 5. Аппаратные рекомендации и Интеграция с ROS2

### Параметры UART
Для обеспечения высоких частот опроса без потерь данных рекомендуется использовать следующие настройки:
*   **Скорость:** 921600 бод
*   **Формат:** 8N1 (8 бит данных, 1 стоп-бит, без четности)
*   **Flow Control:** **RTS/CTS** (Обязательно для предотвращения переполнения буферов)

### Сторона Jetson Orin Nano (ROS2)
На стороне SBC реализуется нода `UartProtocolParser`. Она читает поток из UART (например, `/dev/ttyTHS1`), парсит кадры и публикует их в стандартные топики ROS2. 
*Совет:* Настройте права доступа к UART-порту и используйте ROS2 parameters для динамического конфигурирования датчиков через сервисы.

## 6. Отладка и тестирование

Для первичной отладки подключите UART к ПК и используйте терминал (RealTerm, HTerm, PuTTY) в режиме **Hex Display**.

**Примеры корректных пакетов:**
*   **BMP390:** `AA 55 01 0D [13 байт payload] [CRC]`
*   **MMC5983MA:** `AA 55 02 15 [21 байт payload] [CRC]`

### Чек-лист реализации
**Для STM32H743:**
- [ ] Настроить UART (921600 бод, 8N1, RTS/CTS)
- [ ] Реализовать драйверы I²C для BMP390 и MMC5983MA
- [ ] Внедрить алгоритм компенсации BMP390 и процедуру SET/RESET для MMC5983MA
- [ ] Написать формирователь пакетов и расчет CRC-8/MAXIM
- [ ] Настроить синхронизацию через EXTI для аппаратного таймера (timestamp_us)

**Для Jetson Orin Nano:**
- [ ] Написать парсер протокола (UartProtocolParser)
- [ ] Реализовать ROS2 ноду для трансляции UART в ROS2 topics
- [ ] Настроить права доступа к `/dev/ttyTHS1` или `/dev/ttyUSB0`
- [ ] Протестировать интеграцию и частоты публикации с другими нодами (EKF, навигация)
